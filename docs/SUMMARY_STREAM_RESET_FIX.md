## 补充修复：旧 SSE 快照仍覆盖中途内容

用户后续反馈最终生成已成功，但过程中仍多次全部消失。继续检查发现遗漏了正在运行的旧后端与新版页面组合：8000 端口进程启动于 17:38，阶段历史相关代码在 18:59 修改，而该进程已经提供新构建的页面。旧 SSE 协议只提供 `text/stage/phase`，没有 `parts`；原前端兼容分支每次都构造 `id=1` 的单卡片，从而在分段及修复切换时覆盖全部已读内容。

本次先模拟这一协议进行浏览器复现：第一次修复后本应出现第二张卡片，实际仍只有一张，检查失败 `1 !== 2`。随后补充独立的 `summaryDraft.ts` 快照合并逻辑：

- 对没有阶段列表的快照，按阶段和文本前缀变化保留独立草稿版本；空白及较短的旧前缀不删除已读文本，进入下一分段或汇总时追加卡片。
- 不要求必须收到修复起始的空白帧，轮询遗漏短暂重置时也可识别不同版本。
- 对新版快照按稳定 ID 合并，保留快照暂时遗漏的历史，空白或缩短文本不会使已有卡片消失；重放快照不重复卡片。
- 切换记录、开始不同任务及正式完成仍使用原来的状态边界；不将中间草稿当作正式摘要保存。

本轮验证：前端构建通过；6 项状态边界检查、12 项摘要 SSE 浏览器检查、13 项原流程浏览器回归通过，页面脚本错误为 0；后端摘要与问答流式专项 36 项通过。没有更改生产后端的摘要额度或调用逻辑，也未新增付费调用。上一轮 230 项后端全量及其他独立功能验证见下文。

新增浏览器场景使用五段字幕、两层汇总、三次引用修复，总计十次模拟请求；在生成全程用 DOM 观察器检查每张已出现卡片的文字，验证没有被删除或缩短，并主动断开一次订阅验证重连不会重新生成。最终正式摘要与末尾引用保存成功。

## 原因与证据

只读检查本机学习数据库中这条视频的任务、字幕、用量与缓存：

- 视频约 57 分钟（3,434.579 秒），字幕 1,378 条、18,485 字符。
- 按当前 12,000 字符分段，共两段：11,995／6,501 字符；边界重叠一条字幕。
- 两个失败摘要任务均记录 `AI_OUTPUT_INVALID`，错误为输出不完整；相关调用多次达到原 2,048-token 上限（用量记录出现 2,048／2,049）。
- 第二个任务已成功缓存第一段，但第二段及其修复未完成；原修复使用与第一次相同的输出额度。
- 页面此前在进入下一段、汇总或修复时清空当前草稿，因此自动修复表现为“生成一半突然撤回，从头开始”。

用量与任务记录支持输出截断的判断，但没有持久化原始模型 SSE 帧。修复通过客户端明确识别 `finish_reason=length`，无需仅凭用量猜测；真实模型的内容质量仍需用户验收。

## 修改后的行为

1. 分段初始额度从 2,048 提高为 4,096 tokens，汇总仍为 4,096；每段的简洁程度约束继续保留。
2. 明确达到输出长度上限时，唯一一次修复允许 8,192 tokens；再次失败就停止，不无限调用。结构或引用问题继续只修复一次，网络断流仍不自动重发。问答额度不受影响。
3. 服务端保留当前任务中各分段、汇总和修复尝试的独立草稿；SSE 快照携带稳定卡片 ID、阶段、尝试次数、状态和文本。刷新或重连可以读回活动任务的全部阶段。
4. 页面新增阶段卡片，前一版不会突然消失。未通过校验的版本注明“不会作为正式摘要保存”，已校验分段注明“等待完整汇总”。只有最终通过结构及引用校验的内容生成正式摘要与导图。
5. 已完成分段继续使用原缓存标识，用户手动重试可以复用第一段；不需重新获取字幕或删除记录。任务完成、终止或服务停止时释放内存草稿，不增加 SQLite schema。
