## 1. 实现与展示

原摘要流程先按字幕字符量分段，每段生成笔记并校验，再将笔记每四份逐层汇总。成功分段保存为缓存；全部完成后才保存正式摘要，导图从这份正式内容生成。本次保持这一流程与缓存标识。针对长视频流式草稿撤回问题，分段初始输出额度由 2,048 提高到 4,096 tokens，汇总仍为 4,096；明确达到长度上限后的一次修复提高到 8,192，详见 [修复报告](SUMMARY_STREAM_RESET_FIX.md)。

页面创建摘要时发送 `stream:true`，每个未缓存的分段及汇总请求均使用 DeepSeek 的真实 SSE 传输。服务端从尚未完成的 JSON 中读取概览、总览、章节和知识点，解码中文、换行、引号和 emoji，组合为可阅读的当前阶段草稿；不将原始 JSON、引用 ID 或思考字段显示给用户。

生成过程中显示“总结第 X/N 段”或“汇总第 X 层”，并标注草稿尚未校验。进入下一段、下一次汇总或引用修复时新增独立阶段卡片，保留已有文本；修复前版本明确标注未通过校验，不作为正式摘要保存。已校验或缓存分段单独标注，等待完整汇总。复用已校验分段时不会发出新模型请求。

全部校验成功后，页面更新正式摘要、原文引用和导图。重新生成时，上次已保存的摘要继续可读、可导出；新任务失败不会覆盖旧版本。尚未完成的草稿只存在内存及当前页面，不作为正式历史或导图来源。

## 2. 接口、恢复与失败

| 接口 | 行为 |
| --- | --- |
| `POST /api/v1/analyses/{record_id}/summary` | 原 `force` 参数继续有效，新增可选 `stream`，默认 false 兼容已有调用；返回任务 ID |
| `GET /api/v1/analyses/{record_id}/summary/{job_id}/stream` | 订阅已存在的摘要任务，检查记录与任务类型匹配、本机 Host 和 Origin；不创建模型调用 |
| `GET /api/v1/analyses/{record_id}/summary` | 继续读取当前已保存的正式摘要、导图与用量 |

SSE 事件包括：

- `snapshot`：任务 ID、当前草稿全文、处理阶段及 `parts` 阶段列表（稳定 ID、阶段、尝试次数、状态、文本）；前端按卡片替换快照，重连不重复拼接，也不丢失此前分段。
- `complete`：任务完成、当前已保存的正式摘要/导图及用量；页面重新读取当前记录作为最终状态。
- `failed`：失败或重启中断状态及可公开错误；等待用户手动重试。
- `removed`：记录/任务已删除，停止订阅。
- 注释：连接确认及每 15 秒心跳。响应禁止缓存和转换，发送 `X-Accel-Buffering:no`。

页签切换保持当前订阅；切换记录或退出工作区时取消旧订阅。刷新或返回后通过原任务 ID 接回当前草稿或正式结果，后台继续工作。网络临时中断时自动恢复订阅，并用状态查询回退；恢复期间不会重新 POST 生成摘要。

模型本身断流不自动重发；输出结构或引用无效沿用最多一次修复，保留旧草稿并显示独立的修正版，可能产生额外模型用量。结束原因为 `length` 时增加修复额度，第二次仍失败则停止。长视频后续分段失败时，已成功分段仍可在手动重试中复用。任务终止、删除、完成或停止服务会释放后台草稿。

页面断线与服务重启不同：服务进程重启会中断未完成任务，需手动重试；已保存摘要和已校验缓存可恢复。无需修改 SQLite schema。模型请求上限、超时及用量统计沿用已验证的 DeepSeek 客户端；摘要预算调整不改变问答的 2,048-token 额度。每个阶段草稿最多显示 16,000 字符，不影响最终摘要内容；共享 SSE 解析器允许最多 2 Mi 字符的单个快照，以容纳长视频的阶段列表。

## 5. 用户验收

1. 停止旧后端，在项目根目录运行 `.\start-local.ps1 -Port 8181 -UseFirefoxSubtitleSession`，打开 `http://127.0.0.1:8181`，Ctrl＋F5 刷新。
2. AI 学习中选择已有字幕记录，点击“生成总结”或“重新生成”，查看草稿逐步出现、当前分段/汇总阶段和引用未校验提示。
3. 生成中刷新或退出后返回，应继续同一任务；完成后查看正式摘要、引用和导图。
4. 若重新生成失败，确认旧正式摘要仍可查看与导出；重启中断的任务应等待手动重试。

正式引用仍须结合字幕核对语义准确性；本次验收重点为流式传输、状态恢复和保存行为。
