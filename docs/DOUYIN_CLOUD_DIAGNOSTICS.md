# 抖音分享页偶发空结果：诊断与有限重试

日期：2026-10-11。样例由用户指定：`https://www.douyin.com/jingxuan?modal_id=7693463840301829426`。本次没有新增付费 ASR、LLM 请求或部署操作，也没有重置现有账本。

## 实际证据与结论

用户在宝塔拉取代码后曾收到“抖音分享页未返回视频信息”。用户随后使用主服务 Python，在同一个匿名 HTTP 客户端中连续请求同作品分享页，得到：

| 请求 | HTTP | 页面字符数 | 包含路由数据 | 匹配作品可解析 | 耗时 |
| --- | --- | --- | --- | --- | --- |
| 1 | 200 | 32340 | 是 | 否 | 0.166 秒 |
| 2 | 200 | 37856 | 是 | 是 | 0.411 秒 |
| 3 | 200 | 37856 | 是 | 是 | 0.452 秒 |

随后用户直接请求运行中的 `127.0.0.1:8000/api/v1/parse`，返回 HTTP 200、`extractor=Douyin`、时长 148.028 秒、1 个格式，耗时 0.726 秒。该请求仅解析下载元信息，没有创建学习任务。本地免费探针也曾观察到空页后下一次请求成功。

本次代码完成后，本地新增免费探针真实返回：首次 200/32341 字符但无匹配作品；等待 0.5 秒后第二次 200/37857 字符并解析成功，时长 148.028 秒、1 个媒体地址，总计 2.061 秒，`paid_calls=0`。没有下载或转录该视频。

这些证据表明当时服务器仍能获取该作品，失败具有间歇性。匿名访客状态初始化或上游响应变化是推测，尚不能确定唯一根因。成功与失败页面均可含 `captcha` 等脚本标记，不能据此认定触发了验证码或云服务器 IP 被永久封禁。此阶段未调用 FFmpeg、OSS 或 ASR，不能将该错误归为云密钥或音频转换错误。

## 最小兼容改动

- 沿用同一请求内的隔离匿名 Cookie jar、现有移动端请求头和作品 ID 校验。不会读取 Firefox Cookie，不改变显式 Firefox 模式。
- 分享页仍最多请求 3 次；只有 HTTP 成功但没有匹配作品时，在后两次请求前分别等待 0.5 秒、1 秒。首次成功立即返回，额外等待最多 1.5 秒。
- HTTP 403/429、网络失败、危险重定向、异常大页面等继续直接失败，不自动反复重试，也不绕过访问限制。
- 日志仅记录尝试次数、状态码、页面长度、访客 Cookie 是否存在及作品是否可解析；不记录 Cookie 值、页面正文、媒体地址或凭证。
- 分享页、拒绝访问、网络错误分别有内部错误码；现有 `/parse` 返回结构和用户提示保持兼容。下载、原生字幕与 ASR 音频提取继续复用此适配器。

该改动能缓解短暂空结果，不保证平台风控、作品权限或未来页面结构变化都可自动恢复。

## 免费诊断命令

在服务器 `backend` 目录使用主服务同一个 Python：

```bash
.venv/bin/python -m app.douyin_probe --url 'https://www.douyin.com/jingxuan?modal_id=7693463840301829426'
```

本地可改为 `.venv\Scripts\python.exe`。工具只请求公开分享页，输出脱敏 JSON：每次请求的结构标志、作品编号、时长、可用媒体地址数量、耗时及错误码。不会加载 `.env`、查询/修改数据库、下载媒体、调用 OSS/ASR/LLM；`paid_calls` 恒为 0。成功退出码为 0，失败为 1。不要改成打印页面、请求头或异常全文。
