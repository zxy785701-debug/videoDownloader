# 视频问答 SSE 流式输出方案

日期：2026-10-06。用户已确认：**采用流式展示，保留后台任务，最终校验引用并保存；切换页面或刷新后接回同一任务。**

后续用户已要求摘要也流式输出，当前摘要扩展见 [摘要 SSE 方案与验收报告](AI_SUMMARY_SSE_TEST_REPORT.md)。本文保留问答阶段的设计范围与依据。

## 1. 现有流程与接入范围

原问答流程通过 POST 创建后台任务，DeepSeek 一次返回完整 JSON，服务端校验回答结构、当前字幕引用和证据类型后保存，页面轮询消息列表。已有请求标识防重复提交、每个视频最多一个活动问答、最近五轮成功对话上下文、删除保护、用量记录和重启中断恢复。

本次仅扩展问答的模型传输和展示。新增可选 `stream` 字段，页面使用 `true`；未提供该字段的 API 调用保留原完整回答模式。摘要、字幕获取、导图及视频下载继续使用原流程。

## 2. 实现方式

1. POST `/api/v1/analyses/{record_id}/chat` 发送问题、稳定的 `request_id` 和 `stream:true`，立即返回消息与任务 ID。
2. 后台线程向 DeepSeek 官方 Chat Completions 发出 `stream:true`，保持 JSON 输出、非思考模式和 2,048 tokens 的原问答预算。模型片段来自真实 SSE，未将已完成回答人为拆成动画。
3. 从尚未完成的 JSON 中读取顶层 `answer` 字符串，处理中文、换行、引号、反斜线及 Unicode 代理对；不将 JSON 结构、引用 ID 或思考字段显示给用户。草稿最多展示 6,000 字符。
4. 草稿按消息 ID 暂存于进程内，每个活动任务保存最新完整文本。页面通过 GET `/api/v1/analyses/{record_id}/messages/{message_id}/stream` 订阅；订阅只读取已有任务，断开不会取消生成或创建新的模型请求。
5. 页面逐步展示草稿并标明“正在生成，引用尚未校验”。模型完整结束后校验结构与引用，映射真实字幕时间戳，保存正式回答，再发送完成事件。
6. 引用/结构校验无效时沿用原最多一次修复机制，开始修复前清空上一版草稿；两次都失败则保留失败状态，不保存成功回答或显示正式引用。修复调用可能增加模型用量。

## 3. 事件协议与恢复

| 事件 | 数据与行为 |
| --- | --- |
| `snapshot` | `message_id`、完整草稿 `text`、阶段 `stage`；前端直接替换文本，重连不会重复拼接 |
| `complete` | 从数据库读取的正式消息，包含经校验的回答、证据类型及字幕引用；结束订阅 |
| `failed` | 失败或重启中断的正式消息状态与可公开错误；结束订阅，等待用户手动重试 |
| `removed` | 记录/消息已删除；停止展示与订阅 |
| SSE 注释 | 首次连接确认，以及无内容变化时每 15 秒的心跳 |

传输响应为 `text/event-stream`，禁止缓存/转换并发送 `X-Accel-Buffering:no`。前端使用 Fetch 可读流及 AbortController 解析 SSE，正确处理跨网络包的 UTF-8、CRLF、多行 data 和注释。

切换页签保留当前订阅；切换记录或退出工作区取消旧订阅。返回记录/刷新时查询原消息，重新订阅并读取当前草稿或已保存的最终回答。短暂断线保留当前草稿，约 3 秒后尝试重连；原状态查询作为回退，连接恢复不会重新 POST 提问。状态查询临时失败时也会继续尝试恢复。

## 4. 数据、失败与边界

- 正式回答和任务状态仍保存于 SQLite，不修改数据库 schema。草稿只存在内存，不作为成功问答或后续问题的事实来源；完成、失败、删除及停止服务均释放后台草稿。
- 页面刷新/断线期间，后端存活就继续生成。**服务进程重启会中断当前任务**，草稿不恢复；已有正式回答可恢复，未完成问题需要手动重试，不自动发起可能计费的请求。
- 原密钥隔离、本机 Host/Origin 限制、任务队列上限、请求体大小及超时继续生效。读取 SSE 也检查消息属于当前记录。
- 保持模型响应 2 MiB 上限；流缺少 `[DONE]`、超时、网络错误或非正常结束不会被当作成功。模型断流不自动重新调用。尚未返回完整用量时，数据库不能知道实际计费，以官方账单为准。
- 用量支持当前结束内容帧和较早的独立 usage 帧，每次模型响应只记录一次已返回的合法用量。
- 引用校验验证结构和片段 ID；语义是否准确仍需结合字幕验收。流式草稿尚未校验，只有最终回答提供可点击引用。
