# 《万能视频下载器》AI 视频总结竞品调研

调研日期：2026-10-04。重点对象：[BibiGPT](https://bibigpt.co/) 与 [NoteGPT 哔哩哔哩摘要器](https://notegpt.io/cn/bilibili-summarizer)。本项目当前界面名称为 SaveAny，本文沿用用户提出的《万能视频下载器》作为项目称呼。

本轮交付：竞品公开资料研究、现有项目分析、功能取舍建议和下一阶段确认事项。功能优先级是供用户确认的候选，尚未确定开发范围、AI 服务商或实现方案。

后续确认（2026-10-04）：用户已确定首版支持 B 站、抖音和 YouTube，包含摘要、带时间戳的字幕、可视化思维导图与视频问答，使用 DeepSeek 官方 API；字幕优先由 yt-dlp 获取，暂不加入语音转录；个人本机使用并保存可删除的学习记录。本文第 7 节保留调研阶段的候选排序，最新范围及待审核实现以 [AI 视频学习功能方案](AI_VIDEO_SUMMARY_PLAN.md) 为准。

## 1. 结论与需求对应

用户希望快速理解长视频的讲解内容，获得大纲和核心知识，必要时进一步分析。适合围绕下列学习流程扩展：

**确认视频 → 获得可核对的转录 → 先读总览 → 按章节理解知识点 → 回看对应片段 → 保存笔记。**

两家竞品都围绕摘要、转录、时间戳和知识整理提供能力。BibiGPT 的官方文档还覆盖自定义分析、章节细读和课件关键帧分析；NoteGPT 的 B 站专用页面强调链接输入、带时间戳的摘要、思维导图、翻译和保存到工作区。对我们的启发是：总结需要帮助用户定位和复习原内容，单纯输出一段概述不足以支撑长视频学习。[BibiGPT 总结页面](https://docs.bibigpt.co/getting-started/bibigpt-summary-page-features)、[NoteGPT B 站工具页](https://notegpt.io/cn/bilibili-summarizer)

研究建议：先确认“学习笔记”的核心输出和内容来源，再决定是否加入对话、思维导图和画面理解。具体优先级见第 7 节，不能把候选功能视为已获批准的开发要求。

## 3. BibiGPT：音视频学习与深度处理

### 3.1 输入与流程

官网和快速上手文档描述了视频/音频链接与本地文件入口，覆盖 B 站、YouTube、抖音和播客等来源。基本流程是复制链接、粘贴或使用粘贴按钮、等待生成、查看与导出结果。官方指南写明处理时间取决于内容长度与复杂度，首次使用可能需要账户。具体平台和无字幕长视频的实际可用性需要样例验证。[官网](https://bibigpt.co/)、[快速上手](https://docs.bibigpt.co/getting-started/quick-start-learn-BibiGPT-in-5-minutes)

### 3.2 对长视频学习最有价值的能力

| 能力 | 官方说明中的行为 | 对我们的启发 |
| --- | --- | --- |
| 分层阅读 | 总结页面有总览、章节摘要、字幕和文章等阅读方式 | 短摘要与详细笔记需要不同的信息层级 |
| 原文定位 | 字幕条目带时间戳，可定位视频位置 | 关键知识应能回到来源，便于核对 |
| 章节细读 | 将章节摘要、字幕与润色等放在专注阅读区域；播放时可跟随字幕 | 长内容需要阅读空间与当前位置反馈 |
| 自定义分析 | 可以在总结前或总结后使用自定义指令及模板 | 学习目标会影响输出；可提供“知识整理”等明确模式 |

依据：[总结页面功能](https://docs.bibigpt.co/getting-started/bibigpt-summary-page-features)、[章节细读](https://docs.bibigpt.co/function-usage/platform-function/chapter-deep-reading)、[自定义提示词](https://docs.bibigpt.co/function-usage/platform-function/custom-prompt-summary)。这些是文档功能核对，当前账号权限和每种输出质量未实测。

### 3.3 画面信息是独立的分析范围

官方“PPT 关键帧提取”说明按画面变化提取原视频课件帧，并附对应时段字幕；“截图关键帧分析”说明可以复用这些帧，让视觉模型分析图表、代码和演示。提取原课件与 AI 生成新的演示文稿是不同功能，不能混为一项。[关键帧提取文档](https://docs.bibigpt.co/function-usage/platform-function/ppt-keyframe-extraction.md)、[截图分析文档](https://docs.bibigpt.co/function-usage/platform-function/keyframe-screenshot-analysis.md)

研究判断：访谈和口述讲座通常可以先从字幕/语音整理；代码教程、公式推导和图表讲解可能需要画面信息才能覆盖关键知识。是否包含画面理解，需要用户确认，不能默认把“视频分析”全部解释为语音总结。

### 3.5 可借鉴与尚不能判断的部分

值得借鉴的是总览与细读分层、原文定位、自定义学习目标，以及按需要补充画面信息。官网还描述了向 Notion、Obsidian 等笔记工具保存结果的工作流；对于本项目，先提供可复制和导出的笔记也能形成可用的保存闭环。[官网工作流](https://bibigpt.co/)

目前不能判断：中文专业术语识别质量、长视频尾部信息保留、特定来源的字幕获取成功率、真实处理耗时，以及每个套餐的实付成本。

## 4. NoteGPT：B 站入口与笔记工作流

### 4.1 公开入口与输出

指定页面直接展示 B 站链接输入框、“生成摘要”操作、视频案例及登录入口。页面描述从视频字幕生成内容，提供摘要、完整转录、时间戳、思维导图、翻译和工作区保存；导出说明提到复制、文本、Markdown，以及 FAQ 中的 PDF/Word。实际导出入口、免费权限和无字幕 B 站视频的处理路径未实测。[B 站工具页](https://notegpt.io/cn/bilibili-summarizer)

官方通用使用指南还描述了上传内容、查看并编辑结果、复制或导出，提示用户复核重要内容、对超长文件分段处理。这证明产品的目标包含后续笔记整理，但不能据此认定 B 站专用入口具备通用工具的全部能力。[使用指南](https://help.notegpt.io/how-to-use-notegpt)

研究判断：链接、示例和单个主要操作便于用户尝试；摘要、原文和保存结果形成学习闭环。该 B 站页面没有明确说明课件关键帧理解，因此本轮不把“理解代码/图表画面”计为已确认能力。

### 4.2 “免费”与额度

官方帮助中心写明每账户每月 **15 个免费 quota**。这不是 15 个任意长度视频，也不是无限转录；具体消耗取决于任务。[免费计划说明](https://help.notegpt.io/is-notegpt-free)

公开额度表区分 Basic Quota 与 Premium Credit，并分别列出文本总结、音视频总结、转录、聊天及思维导图的消耗。例如有字幕与无字幕 YouTube 的基础转录计费不同。该表没有列出 B 站专用摘要器的独立消耗规则，不能直接把 YouTube 条目套用到 B 站。[额度政策](https://notegpt.io/quota-usage-policies)

因此，B 站入口的免费宣传只适合描述试用入口，不能作为我们设计“免费处理任意长视频”的成本依据。

## 5. 横向比较与取舍

下表是对上述证据的归纳。各项依据在对应竞品章节给出；“待验证”不能解释为产品一定不支持。

| 维度 | BibiGPT | NoteGPT 指定 B 站入口 | 对本项目的价值 |
| --- | --- | --- | --- |
| 入口 | 多平台音视频、链接及文件 | 聚焦 B 站链接，并提供案例 | 复用现有链接识别，减少重复输入 |
| 大纲与要点 | 总览与章节细读有独立文档 | 宣称带时间戳的结构化摘要 | 核心能力，需要覆盖视频前中后段 |
| 原文核对 | 字幕与播放定位有说明 | 宣称完整转录与时间戳回看 | 提高可验证性，辅助复习 |
| 深入分析 | 自定义提示词、视频问答有文档 | 页面宣称聊天，多语言整理 | 后续按需求加入，先确保内容来源可靠 |
| 思维导图 | 总结页面提供导图形式 | 工具页明确宣传 | 适合作为相同章节结构的另一种展示 |
| 画面理解 | 关键帧提取、视觉分析有专门文档 | 本入口未明确说明 | 是否优先实现取决于课程类型 |
| 笔记保存 | 外部笔记联动与导出 | 工作区、编辑与导出 | 可先满足本地保存与复习 |
| 长视频/成本 | 公开方案按时长与权益区分 | quota/credit 与任务类别区分 | 处理前说明时长与用量，避免重复计费 |
| 开放接入 | 已核对 API 规范和异步任务 | 本轮未核实到该 B 站入口的官方开放 API | 不依赖未公开接口或网页内部请求 |
| 摘要质量 | 待同样本实测 | 待同样本实测 | 不给无依据的评分或速度排名 |

两家的范围都超出单视频概述。我们的差异方向可以是：在现有解析和下载体验中，提供清晰的学习笔记、可信的原文对应关系、可控的处理范围与本地保存。是否做账户、订阅、跨视频知识库和外部笔记同步，留待实际需求确认。

## 6. 现有项目分析：可以复用什么，还缺什么

### 6.1 已核对的项目材料

文档：[项目总结](PROJECT_SUMMARY.md)、[需求](REQUIREMENTS.md)、[下载方案及阶段记录](DOWNLOAD_PLAN.md)、[YouTube 配置](YOUTUBE_SETUP.md)、[YouTube 测试](YOUTUBE_TEST_REPORT.md)、[抖音验收](DOUYIN_TEST_REPORT.md)、[前端验收](UI_REDESIGN_ACCEPTANCE.md)、[README](README.md)。

源码核对覆盖 FastAPI 路由、Pydantic 模型、URL 校验、yt-dlp 服务、抖音适配、前端解析与轮询、结果和错误组件、布局/样式、配置依赖及既有测试契约。

| 项目事实 | 代码入口 | 对总结扩展的影响 |
| --- | --- | --- |
| 返回标题、来源、封面、时长和格式 | [schemas.py](../backend/app/schemas.py)、[parse_video](../backend/app/video_service.py) | 没有返回/保存可供总结使用的字幕正文、章节或统一来源 ID，需要新增内容获取能力 |
| yt-dlp 与抖音分别解析 | [video_service.py](../backend/app/video_service.py)、[douyin.py](../backend/app/douyin.py) | 不同平台的下载成功不代表字幕可取；应分别验证内容来源 |
| “最佳画质”优先视频和音频合并 | [格式映射与下载](../backend/app/video_service.py) | 语音总结不应默认先下载最大画质文件；内容获取策略应独立考虑 |
| 部分任务以 302 交付 | [文件接口](../backend/app/main.py) | 直链任务可能没有本地媒体，不能假设已有文件可用于转录 |
| BackgroundTasks 与内存任务表 | [main.py](../backend/app/main.py)、[任务管理](../backend/app/video_service.py) | 长任务需评估取消、恢复、并发及重试；复用展示方式不等于可以原样复用生命周期 |
| 下载任务创建起两小时到期 | [TASK_TTL 与 expire_task](../backend/app/video_service.py) | 学习笔记的保留时间应单独确定，避免下载清理导致总结记录丢失 |
| 当前页面状态只在 Vue 内存里 | [App.vue](../frontend/src/App.vue) | 刷新不会恢复当前学习记录，需要明确是否要求持久化 |
| 首页使用固定视口，结果在弹窗内滚动 | [App.vue](../frontend/src/App.vue)、[ResultDialog.vue](../frontend/src/components/ResultDialog.vue) | 长篇笔记、原文与播放器并排时，需单独评估阅读布局和手机使用 |
| 默认无 AI 服务依赖/配置 | [后端依赖](../backend/requirements.txt)、[前端依赖](../frontend/package.json) | 需要确认模型、预算、网络与内容出站范围，不能默认已有可调用的 AI 服务 |
| Cookie/代理等通过进程环境读取 | [YouTube 配置文档](YOUTUBE_SETUP.md) | 当前不自动加载 .env；新增 AI 配置的载入、校验与报错须明确 |

当前产品没有内置视频播放器、字幕搜索、语音转录、摘要、问答、总结缓存或历史库。首页样式和组件已具备响应式、焦点与错误反馈基础，可以复用其视觉和交互规范。

既有文档记录 2026-10-03 后端 **80 项测试通过**、前端构建通过；YouTube 登录态下载和抖音真实下载有不同层级的验收证据。本轮阅读了测试及报告，没有重跑媒体下载或把既有 80 项测试当作 AI 功能测试。

### 6.2 从本项目出发的研究判断

建议评估内容获取顺序：可用平台字幕 → 无字幕时获取音频并转录 → 必要时补充关键帧。此顺序是候选方案，不是对每个平台字幕权限或转录质量的保证，必须以授权样例验证。

“快速理解”应能在用户未完成高画质下载时启动。总结和下载可以共享已确认的视频信息，但不应把两者绑成必须先完成完整视频下载的单一路径。

长视频还需要按章节或时间区间处理、保留覆盖范围和来源时间，防止只整理开头或对缺失片段补写。正文、原文证据及推论应可区分；当内容获取失败时应给出失败原因，而不是仅凭标题生成一份看似完整的摘要。

### 6.3 内容处理与保存范围

两家竞品的隐私说明都涉及上传/输入内容的服务端处理与保存；NoteGPT 明确列出可能发送给第三方 AI 处理服务，BibiGPT 说明会使用转录/总结处理商。不能把“通过网页使用”理解成内容始终只留在本机。[NoteGPT 隐私说明](https://notegpt.io/cn/privacy)、[BibiGPT 隐私说明](https://bibigpt.co/privacy-policy)

对于现有个人本地下载器，需要在设计前确认允许发送的是字幕文本、音频还是视频画面，以及结果是否仅本地保存。模型凭据应由后端管理，并与平台浏览器会话隔离；该项属于拟议实现约束。

## 7. 首版候选功能与后续方向

以下优先级由研究提出，待用户确认。P0 表示建议先做，P1 表示在基础体验通过验收后评估，P2 表示取决于特定场景。

| 优先级 | 候选能力 | 对应学习价值 | 进入开发前的条件 |
| --- | --- | --- | --- |
| P0 | 一句话结论 + 简明总览 | 快速判断是否值得继续学习 | 确认输出语言与摘要详细程度 |
| P0 | 章节大纲、各章要点及时间范围 | 理解知识结构，按需回看 | 有完整内容和可核对时间轴 |
| P0 | 核心概念、方法、例子及适用条件 | 获得可复习的知识笔记 | 不凭空补概念；保留原文依据 |
| P0 | 原文转录与来源/覆盖范围说明 | 核对细节与发现转录错误 | 确认字幕优先及无字幕转录策略 |
| P0 | 时间戳定位与复制/Markdown 导出 | 找原片段、保存学习成果 | 确认站外回看或站内播放器方式 |
| P0 | 真实处理阶段、失败原因与重试 | 用户知道任务为何等待或失败 | 不模拟进度；重试避免无谓重复处理 |
| P1 | 针对视频的问答 | 解释不理解的概念和推理 | 需要限定依据范围并支持来源引用 |
| P1 | 思维导图、字幕搜索、总结历史 | 快速复习、检索、复用 | 确认持久化要求与结构化结果模型 |
| P1 | 学习目标/分析模板 | 根据目标提取方法、论点、行动建议 | 确认用户需要的模板类型 |
| P2 | 课件/代码/图表关键帧理解 | 补足口播未覆盖的视觉知识 | 如果用户主要学此类课程，应重新提升优先级 |
| P2 | 测验/闪卡、跨视频整理、外部笔记同步 | 自测与积累知识库 | 基础总结准确度和使用频率已验证 |

此处不确定具体 API 路径、数据表、模型、费用阈值或页面稿；这些属于下一轮方案设计，需用户确认范围后再制定。

## 8. 后续实测与验收建议

本节是测试计划候选，不是本次已执行的测试结果。竞品实测需要用户确认账号使用、额度和允许提交的视频；本项目实现后再独立执行自动测试与真实样例检查。

| 样例类型 | 核对重点 |
| --- | --- |
| 有平台字幕的中文长讲座 | 大纲层级、核心知识召回、时间戳对应、全片覆盖 |
| 无字幕的中文讲解 | 转录路径、术语错误、转录耗时与费用 |
| 英文/中英混合技术课程 | 中文笔记质量、专业词保留、翻译与原意一致 |
| 主要知识在 PPT/代码画面中的教程 | 语音总结的遗漏，视觉模式的补充作用 |
| 两小时以上且主题切换明显的视频 | 后半段遗漏、重复要点、跨段上下文衔接 |
| 链接失效、需登录、空字幕、无语音等 | 是否准确说明失败或内容不足，而非生成虚构总结 |

每个样例由人工准备参考知识点和时间片段；对两家竞品使用同一输入，记录使用套餐、设置、冷/热处理时间、费用/额度、输出覆盖范围及实际结果。应分开评估“原内容可获取”和“AI 整理质量”，避免将缓存命中或网络问题误判为模型能力。

实现后的测试至少需要覆盖：时间轴与字幕解析、空内容处理、长文本分段与全片覆盖、模型超时/失败、重复请求/重试、任务状态、结果保存与导出、原文引用及下载功能回归。数量阈值、最长视频与可接受等待时间由用户确认后写入验收标准。
