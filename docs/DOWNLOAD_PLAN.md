# 视频下载交付方案

> 当前实现状态（2026-10-03）：单视频解析、格式选择、服务端下载与文件交付已完成，支持 yt-dlp 平台适配及独立抖音适配；80 项后端测试和前端生产构建通过。本文保留早期方案与阶段记录，最新能力、验收证据和限制见 [项目完成总结](PROJECT_SUMMARY.md)。历史记录中的测试数量及界面形态不代表当前版本。

本地运行方式：在仓库根目录运行 `backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --reload --reload-dir backend/app --port 8000`，将热重载范围限制在后端源码目录，避免 `.venv`、`.local` 和前端依赖变动触发进程重启。另开终端进入 `frontend` 运行 `npm run dev`。API 文档地址为 `/docs`。

YouTube 若要求登录验证，默认不读取任何浏览器 Cookie。显式配置 `YTDLP_COOKIES_FROM_BROWSER` 后读取所选本机会话。支持 YouTube 专用代理与可选 bgutil PO Token 服务；自动模式直接服务端下载，显式直链模式返回操作提示。配置步骤和限制见 [YouTube 配置与排障](YOUTUBE_SETUP.md)。依赖使用 `yt-dlp[default]` 提供 EJS 脚本，并在可用时启用本机 Node runtime。没有可用登录会话时，该视频仍可能无法解析。

实现范围以代码为准；如本文的后续设计和当前行为有冲突，必须先更新实现或明确标记为待办，不得把规划中的能力描述为已上线。

## 1. 目标与结论

首版同时支持服务端下载和直链跳转，并以 `auto` 为默认策略：

- 当解析结果是浏览器可直接访问的普通 HTTP(S) 文件链接，且不依赖平台 Cookie、特殊请求头或音视频合并时，采用 302 跳转。
- 其他情况由 yt-dlp 在服务端下载到临时目录，完成后向用户提供短期下载链接。
- 代理下载作为可选增强模式单独设计。它不需要保存完整文件，但所有视频流量仍经过本服务，会消耗带宽；首版仅在确有平台需求、并完成 Range 与访问控制验证后开放。
- 不承诺支持所有平台。yt-dlp 的站点提取器会随平台变化，遇到不支持、受限或加密内容时应明确返回失败原因，不绕过 DRM、付费墙或平台访问控制。

## 2. 三种交付方式比较

| 方式 | 服务端磁盘 | 服务端带宽 | 体验与适用范围 | 主要限制 |
| --- | --- | --- | --- | --- |
| 服务端下载后提供链接 | 需要临时空间 | 消耗 | 体验稳定，可统一文件名、下载头和进度，适用于 yt-dlp 可处理的格式 | 文件占空间；需清理、配额和并发控制 |
| 解析后 302 跳转 | 不需要 | 基本不消耗视频带宽 | 普通、可公开访问的直链最快 | 直链会暴露给浏览器；签名链接会过期；需要 Cookie/特殊请求头时通常失败；目标站可能以内嵌播放方式打开而非下载 |
| 服务端流式代理 | 不需要保存完整文件 | 消耗全部视频带宽 | 可隐藏上游直链，并由本服务控制下载文件名和响应头 | 必须正确转发 Range/206 等请求；需控制并发和带宽；上游仍可能要求认证、请求头或特殊分段处理 |

“代理不占服务器空间”不等于“没有服务器成本”：代理的出站流量、连接数和带宽仍由本服务承担。302 跳转才是不转发视频流量的方案，但无法保证各平台均按附件下载。

## 3. 自动选择规则

解析阶段使用 yt-dlp 获取元信息与格式清单，不把上游 `format.url` 或平台 Cookie 返回给前端。下载请求可选择 `auto`、`server` 或 `redirect`；默认 `auto`。

`auto` 的判定顺序：

1. 仅考虑协议为 HTTP(S) 的单文件格式，不把 `file://`、内部地址或未知协议作为交付目标。
2. 只有在该格式无需平台 Cookie、无需额外 `http_headers`、不依赖 HLS/DASH 分段、不需要 FFmpeg 合并，并且上游主机通过安全校验时，才选择 302。
3. 任一条件无法确认或不满足，就回退到服务端 yt-dlp 下载。
4. 服务端下载失败时返回可读错误，不自动尝试访问控制绕过；如有代理模式需求，后续按具体平台做受限支持。

平台差异很大，自动策略应保守。不同 extractor / 格式的判定记录在服务端日志和任务结果中，但不得记录含签名参数的完整直链。

## 4. 核心 API 草案

统一前缀：`/api/v1`。所有请求和响应均为 JSON，视频文件除外。

### `POST /api/v1/parse`

请求：

```json
{
  "url": "https://example.com/video"
}
```

响应包含标题、封面、时长、平台标识、可选格式（`format_id`、分辨率、编码、估算大小）以及本服务建议的交付方式。格式中的上游直链和认证信息只保留在服务端。

Bilibili 等来源可能只有分离的视频轨和音频轨。UI 将这类清晰度表示为 `video:<format_id>`，后端映射为 `<format_id>+ba/best`；“最佳画质”映射为 `bv*+ba/best`，以优先合流并兼容单文件回退。缩略图通过 `GET /api/v1/thumbnails/{token}` 同源返回：解析时登记上游图片 URL，token 有效一小时；服务端向公网地址发送带来源站根地址的 Referer，只接受允许的图片 MIME 和 8 MiB 以内的内容，并验证重定向目标。前端不直接请求 Bilibili 图片 CDN。

### `POST /api/v1/downloads`

请求：

```json
{
  "url": "https://example.com/video",
  "format_id": "best",
  "delivery_mode": "auto"
}
```

服务端校验 URL 和格式后，返回任务标识、状态及本服务的下载入口。服务端下载作为后台任务执行；直链模式也由短期令牌关联解析结果，不接受客户端传入任意上游 URL。

### `GET /api/v1/downloads/{task_id}`

返回 `pending`、`processing`、`ready` 或 `failed` 状态，以及可选进度、错误码和过期时间。状态先放在单进程内存中，不引入数据库；进程重启后任务状态会丢失。

### `GET /api/v1/downloads/{task_id}/file`

服务端下载完成后，以附件形式返回临时文件。直链任务经过令牌和有效期校验后返回 302；上游目标只由服务端保存和选择。

代理模式如纳入后续迭代，使用相同的本服务下载入口，并按需实现 Range 请求转发和 206 响应，不另行暴露上游 URL。

## 5. 后端处理与资源生命周期

- FastAPI 提供 API 和 OpenAPI 文档；下载本身交给 yt-dlp Python API，使用其 progress hook 更新任务状态。
- 任务文件名由服务端根据安全化后的视频标题生成，不使用用户提供的路径。
- 文件存放在独立临时目录，默认两小时过期；当前在创建新任务以及查询状态/文件时清理过期任务和文件，没有后台定时清扫器，因此低流量时过期文件可能暂留到下一次 API 活动。正式部署前应增加定时清理和磁盘配额。
- 首版用进程内任务表，因此只适用于单实例演示或低并发使用。公开部署前需增加磁盘总量与单任务上限、并发/速率限制，以及跨进程任务存储方案。
- 需要合并分离的视频/音频时使用 FFmpeg：优先系统 PATH 中的版本，其次使用 `imageio-ffmpeg` 随包二进制，也可通过 `YTDLP_FFMPEG_LOCATION` 指定路径。若仍不可用或格式不支持，应返回明确错误。

## 6. 安全与合规边界

- 仅接受 `http` / `https` 输入；拒绝 localhost、私有/保留 IP、云元数据地址和非公网目标，解析与下载阶段均需检查目标主机及重定向，降低 SSRF 风险。正式部署还应配置出站网络限制。
- 不提供任意 URL 代理接口；下载和 302 入口使用不可预测、短时有效的任务令牌，并校验过期状态。
- 前端不接收也不持久化平台 Cookie、登录凭据或上游签名 URL；日志对 URL 查询参数脱敏。
- 设置请求体、时长、文件大小、并发数和保留时长上限；对于直播、播放列表或多文件输出，首版拒绝或要求用户选择明确的有限范围。
- 页面说明仅下载用户有权保存的内容并遵守平台规则。首版不支持 DRM 内容、付费墙内容或绕过平台访问限制。

## 7. 前端方案

- Vue 3 + TypeScript + Vite + Tailwind CSS；桌面与手机共用一套响应式界面。
- 参考页面的白底、清晰顶栏、醒目标题、居中 URL 搜索入口、内容卡片网格；视频解析后在页面内展示封面、标题、平台、时长和格式选择，不做营销式长落地页。
- 下载方式默认“自动”，可提供“自动 / 兼容优先 / 直链优先”的简明选项；当直链可能无法作为附件下载时，在选择前说明限制。
- VIP 区域首版仅作为非交易性质的方案展示/占位，不接真实支付，不虚构可用权益；只有确认付费规则、退款和合规方案后才接支付。
- 历史记录首版可使用浏览器本地存储，并提供清除入口；不保存上游地址中的敏感参数。

## 8. 阶段与验收标准

### 阶段 1：FastAPI 与 yt-dlp

实现解析、创建下载任务、查询任务/交付文件三个核心 API；包含 `auto`、服务端下载和安全直链跳转的基础逻辑、错误处理与临时文件清理。

验收：用可公开访问且获准测试的视频，能解析格式；服务端模式完成下载并提供附件；合格直链模式返回本服务 302；不合格直链回退到服务端模式；非法 URL、未知格式、过期令牌和上游错误有明确响应。

### 阶段 2：Vue + Vite + Tailwind 页面骨架

建立响应式首页、链接输入区、解析结果和格式选择布局，接入 Tailwind Vite 插件。

验收：前端生产构建成功；手机和桌面视口无横向溢出，主要操作清晰可见。

### 阶段 3：前后端联调

实现 URL 解析、格式选择、下载任务创建和下载入口的完整流程，展示加载、空结果、失败和过期状态。

验收：通过浏览器完成一次端到端公开样例下载；API 错误映射到可理解的界面提示。当前仍需用有权测试的真实公开视频完成这一项。

### 阶段 4：视觉完善与产品引导

完善参考站点风格下的版式、平台展示、空状态和 VIP 介绍。VIP 暂作视觉/权益说明，不接支付。

验收：桌面/移动截图检查布局、图片、文字截断和主要交互；VIP 内容不会误导用户认为已经开通付费。

### 阶段 5：扩展体验

增加字幕文件下载、明确的下载进度展示、浏览器本地历史记录、清理入口及移动端细节。根据实际需求再决定字幕翻译、视频总结、代理传输和账号付费。

验收：字幕来源与语言选择明确；进度状态可恢复到用户可理解的终态；历史记录可清除；移动端下载链接和操作可用。

## 9. 待确认的产品决策

1. 默认交付采用 `auto`，YouTube 直接服务端下载，其他平台由“安全直链 302 优先、否则服务端临时下载”执行。
2. 临时下载文件默认保留 2 小时；无数据库阶段，服务重启会清空任务状态。
3. 代理模式首版不默认开放，待确定确有平台需要后再实现 Range 转发和资源限制。
4. VIP 首版只展示方案，不接收支付。
5. 支持单条公开链接，Cookie 仅按显式配置读取本机会话；不处理 DRM、付费墙或访问控制绕过。
