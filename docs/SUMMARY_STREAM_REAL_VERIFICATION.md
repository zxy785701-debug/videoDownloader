## 原因和修复

1. **运行中的后端仍是旧代码。** 8000 端口原进程启动于 17:38，未加载之后修改的输出额度和阶段历史；最近失败调用仍耗尽 2,048-token 额度。前端现在读取 `summary_stream_version=2`，旧运行时会提示重启并阻止付费生成，字幕仍可查看。
2. **无关模型字段触发整段重写。** 第一轮真实调用返回完整 JSON，但多了根字段 `type: "json_object"`，被严格 schema 拒绝。现在先提取正式摘要所需的根、章节、要点字段，再进行原结构、长度、非空和引用校验。不填补正文、不删掉异常章节、不替换引用。捕获的真实返回重新校验成功：6 章、82 个有效引用 ID，预览正文不变。
3. **前端把文字变化猜成修复。** 旧协议没有尝试编号，文本前缀变化也可能来自 JSON 字段到达顺序。现在只保留此前文本，不据此标注“修正”；真正修复由后端明确报告尝试次数和原因，旧草稿持续可查看。
4. **完成时并行读取有先后差异。** 记录状态与摘要读取可能跨过正式保存时点。现在先接收 SSE 中的正式结果，再清理草稿；发现记录已完成而摘要尚未读到时重新读取，忽略过期并行响应。

摘要仍使用两段笔记和一次最终汇总。开始新阶段会新增卡片；结构或引用错误最多修复一次，明确输出截断时可将 4,096-token 额度提高到 8,192。问答流程、下载功能和字幕原文未改变。
