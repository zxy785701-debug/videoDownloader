# B 站 ASR 音频备用地址修复

日期：2026-10-10。对应用户提供的视频 `BV1N2pc6gErK`。本次只修复 ASR 音频提取，不修改下载、Firefox Cookie、元信息 API、总结接口或费用账本。

## 问题与修复

宝塔页面已成功获取视频信息，但字幕兜底提示“音频与识别结果必须使用公开 HTTPS 地址”。本地使用匿名元信息 API 检查同一视频，发现该音轨的首选 CDN 地址为 HTTPS `:8082`，第一个备用地址为 HTTPS `:4483`，第二个备用地址使用标准 HTTPS 端口。原 ASR 提取器只请求首选地址，因此被只允许标准 HTTPS 的安全校验拒绝。

`backend/app/asr/audio_worker.py` 现在从同一音轨的首选地址及平台已有 `_platform_backup_urls` 中选择标准 HTTPS 地址，继续优先音频轨。不会改写地址的协议、端口、路径或签名查询参数。每次提取最多尝试 4 个不同的合规地址；只有媒体不可用或连接失败才尝试下一个地址，并删除上次下载的残留文件。磁盘空间或权限错误给出明确提示。

原有 DNS 公网检查、连接 IP 固定、TLS 证书校验、逐跳重定向检查、文件大小、任务时限及 FFmpeg 单线程限制保持有效。内网地址、安全检查失败、文件超限或任务终止不会触发备用重试。OSS 上传和付费 ASR 提交仍在成功提取音频之后，本次备用下载不会增加云端提交次数。

## 宝塔更新与验收

1. 确认本修复已推送，在当前音频任务结束后，进入宝塔现有项目根目录执行 `git pull --ff-only`。如存在本地修改或分支不一致导致拉取失败，先保留现场检查，不要强制重置。
2. 本修复的运行代码只有 `backend/app/asr/audio_worker.py`。现有主服务每次提取音频都会新建 `python -m app.asr.audio_worker` 子进程，因此新任务直接加载更新后的文件。无需重装依赖、构建前端、重启 8000 主服务或修改 Nginx、SSH 隧道和环境变量。应确认拉取目录就是当前服务使用的项目目录。
3. 回到该视频页面，点击“重试获取字幕”，等待音频提取和云端转录；字幕成功后检查时间轴。如果摘要没有自动生成，点击“生成总结”。原记录的失败后手动重试不保证重新开启自动总结。
4. 此次服务器重试可能产生首次识别费用；只提交一次并等待。若出现新错误，保留错误文本、发生时间和任务状态，先核对原任务再决定重试。不要删除或重置 `asr.sqlite3`、学习库或已有测试账本。

这份补丁没有新增生产配置。管理员仍需确认实际运行目录、原有百炼/OSS 配置和该任务的真实云端结果；现有应用预算与云商账单限制的边界不变。
